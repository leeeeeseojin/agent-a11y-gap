# 연구 계획

결과물은 해당 레포, 분석 노트북 3개, 2~4쪽 리포트(`report/`).
왜 시작했는지는 [origin.md](origin.md)에 있다.

## 연구 질문과 가설

| | 질문 | 가설 |
| --- | --- | --- |
| RQ1 | 브라우저 MCP 스냅샷은 어떤 숨김 패턴에서 표준 접근성 트리와 다른가? | aria-hidden·inert·네이티브 모달처럼 속성으로 숨긴 요소는 스냅샷에 남고, CSS로 렌더를 막은 요소는 사라진다. |
| RQ2 | 그 차이가 에이전트의 성공률, 거짓 성공 보고, 턴 수에 영향을 주는가? | 배경 요소가 노출되면 모달 과제에서 오클릭, 시간 초과, 거짓 성공이 늘어난다. |
| RQ3 | 사람과 에이전트 모두에게 배경을 숨기는 설계는 무엇인가? | 배경을 실제로 렌더하지 않는 설계는 격차를 없애지만, 사람 쪽에서 맥락이 끊기는 비용이 생긴다. |

## 세 층

앞 층에서 차이가 난 조건만 다음 층으로 넘긴다. 모델 비용이 드는 2층을 작게 유지하려고.

**1층. 스냅샷 비교** (`probe/layer1.ts`, LLM 없음)
패턴 14종 × 도구 4종(CDP 전체 접근성 트리, Playwright getByRole, Playwright MCP, Chrome DevTools MCP).
노출 여부, 접근성 이름 유지 여부, 클릭용 ref 여부, 그 ref를 눌렀을 때의 결과를 기록한다.

**2층. 에이전트 과제** (`bench/`)
모달을 거쳐야 하는 과제 4개(배경과 시트에 같은 이름의 버튼이 있는 경우 포함).
기본 실험은 과제 4 × 모달 구현 4 × 모델 3 × 3회 = 144회(Playwright MCP).
보조 실험은 1층에서 차이가 난 조건만 Chrome DevTools MCP로 모델 1종 × 3회.
채점은 에이전트의 보고가 아니라 서버 상태로 한다. 지표는 확인된 성공, 거짓 성공 보고, 턴 수, 막힌 클릭 수, 시간 초과.

**3층. 설계 대안** (`cases/modal/`, `probe/layer3.ts`, `e2e/`)
같은 화면에 모달 구현 A~D를 적용한다.
A aria-modal만, B 배경 inert·aria-hidden, C 네이티브 dialog, D 배경 언마운트(별도 화면).
사람 기준(배경 숨김, 포커스 가둠, Esc 닫힘과 포커스 복귀)과 에이전트 기준을 한 표로 묶는다.

## 미리 정해 둔 것

- **inert는 이미 보고된 문제다.** Playwright 이슈 [#36938](https://github.com/microsoft/playwright/issues/36938)이
  inert 요소가 접근성 트리에서 숨겨지지 않는 버그를 다룬다. 리포트에서는 인용하고 새 발견으로 주장하지 않는다.
- **aria-hidden과 네이티브 dialog는 선행 이슈를 아직 못 찾았다.** 착수 전에 playwright와 playwright-mcp 이슈를 다시 검색한다.
  비공식 정리 문서 두 곳은 스냅샷이 aria-hidden 요소를 뺀다고 적었는데 실제 동작은 달랐다. 공식 문서와도 대조한다.
- **결과는 특정 버전의 값이다.** 버전을 결과 폴더 이름에 넣고, CI가 매주 최신 버전으로 다시 돌려 달라진 칸을 남긴다.
- **표본이 작다.** 조건당 반복이 적어 모델 순위나 정확한 성공률로 읽지 않는다. 실패 과정의 차이를 중심으로 해석한다.
- **에이전트는 자체 테스트 페이지에서만 돌린다.** 사람 참가자가 없는 연구다. 설계 대안 D의 "맥락이 끊기는 비용"은
  여기서 잴 수 없고, 후속 사용자 연구의 질문으로 남긴다.
- **결과는 이슈로 제보한다.** 재현 페이지(`cases/patterns/`)를 붙여 Playwright MCP에 제보한다.
